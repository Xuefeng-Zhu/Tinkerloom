# Explicit manual editing of a published app

The original Flutter mini-app's `customize()` guards record navigation, then calls `builder.begin(existing appId)`. The legacy server's `begin` takes the active published definition for an existing app (rather than the supplied starter key), saves its canonical definition/base version into an author draft, and synchronizes definition media. That source behavior is the reference for this correction; it is not proof of the replacement backend.

A builder with no current private candidate can now try the already-validated current published declaration in the isolated preview. A visible version caption identifies that fallback. No author draft, operation ID or write is created by loading the app, entering Build, or opening Preview. An existing author candidate remains the first preview choice; a blank shell still has no placeholder declaration. The preview continues to use synthetic records and the isolated factory. The host preloader uses the same selected declaration and only saved/broker-confirmed asset IDs, so published static images can be injected without putting an authenticated adapter, storage, picker, device bridge or callback into the preview.

The explicit **Edit published version** button is available with AI disabled. It captures the displayed immutable version ID/hash/definition, refreshes current authority and joins read-only record-command recovery. A changed publication, a newly discovered own draft, pending command, local invalid/dirty input, active generation, unsaved record form or image interaction prevents the copy. Repeated clicks join the same preparation. A failed authority read cannot authorize copying cached metadata. Account/access/author loss still fences late responses and clears private preview access.

After those checks, the exact published spec becomes the local candidate and is saved through the existing durable `spec.saveDraft` path with `expectedRevision:0` and the captured `expectedVersionId`. IDs, custom fields/form steps/pages/actions/appearance and static image references are retained. The original operation/spec/base are persisted before transport, and a later publication cannot silently become this operation's new base. Lost responses retain that exact envelope; reopen performs no automatic replay, and explicit recovery retries it. Existing private work is never replaced by this entry action. Publication remains a separate reviewed operation. No new RPC, model request, provider capability/configuration, live record copy or historical data cutover is introduced.

The starter catalog is shown for blank shells, rather than being the only manual-edit entry for a published custom app. The published fallback and private candidate use the same isolated preview component position, allowing the existing presentation-preservation logic to retain its session when the exact declaration is copied.

## Local verification

Eleven new test groups use a customized Photo Journal that is absent from the catalog: an added optional field, matching custom form-step binding, and a banner with an approved static image ID. They cover read-only fallback, exact owner/builder save, own-draft priority, stale publication/new draft, failed authority read, role/archive/account fencing, pending record/full operations, active generation, image/form work, repeated clicks, lost-save retry after reopen and a newer publication, publication racing durable preparation, authorized host-only static-image injection, and the actual rendered manual-entry panel/provider-disabled composer. The static-image reader is injected test infrastructure; it is not Cloud media proof.

All 656 local tests pass (645 baseline plus eleven new groups), with zero skips/todos. TypeScript, Expo ESLint with zero warnings, and Prettier checks pass. The exact old Controller/GenerationPanel fail the targeted fallback/action regressions; `baseline-regressions.log` is retained in the frozen temporary stage. These are local controller/render tests. Root must verify the real browser Edit published version flow and create final web/iOS/Android exports/native packages from the new combined source. The earlier `10fed99` native checkpoint does not contain this correction. No persistent edits, Git, Cloud/provider calls, dependency changes, native actions or device proof were performed in this slice.
