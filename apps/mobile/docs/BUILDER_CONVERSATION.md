# Builder conversation and preview checkpoint (B04)

This slice ports the session conversation and responsive Chat/Preview arrangement from `legacy_appnest/docs/CREATION_FLOW.md` and the Flutter builder's `acceptRequest` / `updateSnapshot` behavior. It does not configure a model provider or demonstrate a live generation.

`FullAppController` projects confirmed accepted generation requests into account/app/author session memory. Exact untrimmed request text appears with a factual observed server outcome. A new accepted request clears the composer only if it still contains that same request; a different unsent request stays intact. A fresh controller can restore only the latest authorized server job, clearly labeled as restored, rather than invent earlier session history. Up to 50 entries / 512 KiB of request text are retained; oldest complete entries are omitted with a visible count. No history is written to storage, URLs, logs or provider context, and this projection excludes provider diagnostics, credentials, live records and devices.

The existing encrypted exact generation command is unchanged. Unknown responses do not enter accepted history, even if a later read happens to show a matching job. Recovery remains read-only until the user explicitly checks the original outcome. The response must confirm the original request/revision and the same job in its app envelope; clearing the durable journal and a fresh authorized manifest must both succeed before a new accepted entry appears. Failure to clear local recovery stays uncertain. A later read failure cannot authorize private display from an old receipt. Account disposal, access loss, archival or loss of builder authority clear history in memory; unresolved encrypted commands remain available under the existing recovery policy. A stale latest job has no current progress card; earlier confirmed outcomes remain session history within the same authorized scope.

A blank shell now sends `startFromScratch:true`, as required by the actual backend `spec.generate` editing/base checks; a saved template/manual candidate uses edit mode. The misleading generic fresh-candidate toggle was removed: a published base or an established backend generation session determines edit semantics regardless of that toggle. This changes no provider capability flag and sends no request automatically.

`BuilderWorkspace` keeps one isolated preview subtree and one chat/editor subtree at stable sibling positions. At 850 logical pixels and wider, Chat and Preview appear side by side (330/380 pixel chat column as in Flutter). Phones use explicit Chat/Preview tabs; large font scale also uses tabs. Native selected/disabled accessibility state and explicit web ARIA aliases are supplied. Hidden panes are excluded from accessibility. The existing isolated preview receives only the validated declaration and authorized frozen static-image map; no live adapter, host store or device bridge enters it. Existing presentation/semantic restart behavior remains in `PreviewSession`. Live runtime and its activity lease stay in their existing branch. Generation status polling stops when the builder is not focused or Live mode is selected; it never enqueues generation. Poll responses apply current authority while preserving local rejected/dirty editor input, including structural changes that arrive after a poll began.

The existing guarded mode/navigation callbacks are used for both mobile tabs and top app modes. Raw inspector guards, explicit discard, save/publication review, current access and retained-command locks are preserved. The root's frozen `formBusy` navigation changes are composed into the `FullAppScreen.tsx` baseline before this patch; only its import and builder/preview presentation section change. Nine renderer/runtime form-busy files and root navigation helper/tests were copied as dependency-only verification support and are excluded from this handoff.
