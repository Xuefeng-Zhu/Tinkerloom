The Build URL already contained canonical `page=todayPage` before the copy. A confirmed save acknowledges and clears its journal, disposes runtime A, then loads current published metadata and capabilities before installing runtime B. During that legitimate runtime-null interval, `app.version` remains present. The route effect previously treated every missing runtime with an available app as an unpublished app, so it could reject and rewrite a valid canonical page before runtime B was ready.

The missing-runtime branch now waits when metadata is absent **or the validated app has a published version**. Its small extracted guard `waitForRouteRuntime()` is used only in that branch. Waiting releases the handled-route claim and returns; it does not change the URL, error, mode, command, controller or navigation intent. Existing runtime/effect readiness can then process the original request. No navigation queue or automatic replay of a blocked pending navigation is introduced.

An actual `app.version === null` still follows the existing unpublished-page/record behavior. Current access denial still clears private app/runtime state and exposes its real controller error. Published viewer metadata can wait for a read-only replacement without gaining builder access. Once a runtime is present, the original current-authority manifest load, authorized record lookup, strict page/record identities, external/protected-visit handling, pending/form/image/dirty guards and cancellation epochs remain unchanged.
