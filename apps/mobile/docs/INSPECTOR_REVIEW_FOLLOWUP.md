# Inspector integration review follow-up

Two material gaps were reproduced against the integrated source before this patch. A prepared review could still dispatch `spec.publish` after a rejected label: the last valid candidate stayed clean and the old review remained, but `publish()` did not check `editorError` or mounted raw-input guards. The publication panel also left review controls enabled. The controller now rejects publication before allocating an operation ID or sending a request, and the panel disables its controls while either invalid-input signal is present. This keeps the controller barrier independent of UI approval state.

The other gap required an invalid label followed by an unrelated valid no-op. That no-op cleared the general error and left `dirty` false while the mounted raw input remained rejected. A subsequent changed authoritative definition then advanced the reset epoch, silently replacing the invalid text. The reset predicate now also requires no rejected mounted input. The new authoritative definition can refresh behind the local buffer, but the rejected text remains available until repair or explicit Discard.

All four new regressions fail against the exact unmodified baseline and pass with this patch: rejected semantic label publication, raw-guard-only publication, background replacement after a masked general error, and actual RNWeb publication controls. The composed client suite passes all 606 tests with no failures, skips or cancellations, plus typecheck, lint and owned formatting. Baseline failure output is retained in the isolated stage as `baseline-regressions.log`; it is a local injected-transport reproduction, not a Cloud incident.

The independent source review found the integrated epoch/guard props, subscribed boolean notifications, `canLeave`, host/external navigation conditions, Discard enabling and save-path guard consistent. Root separately owns the visual Save-button disabled condition. Runtime navigation paths remain the other review agent's scope. Real browser invalid-label blur/fix/Discard, approved-publication blocking and Back/Forward behavior still require post-merge browser proof. No persistent source edits, Git/Cloud/provider calls, dependency or native actions were performed.
