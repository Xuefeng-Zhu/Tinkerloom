# In-app notifications integration

All source in this directory is framework-independent transport/controller code or React Native UI. It never creates an SDK client, sends email/push, or connects to a provider.

Root should construct one `NotificationsController({scope:{endpoint,projectId,accountId}, transport, newId, lifetime?, onUnauthenticated?})` for each authenticated session epoch and retain it across routes. The transport must check that same account/epoch before and after settlement. The default host is encrypted durable account storage under the reserved app scope `inbox`; optional injected `host` must match that exact endpoint/project/account/namespace. An injected `lifetime` can dispose the controller immediately when the account closes. `newId` must use the real cryptographic operation-ID factory. `onUnauthenticated` expires the account on 401; app-only 403/404 hides inaccessible data without globally signing out.

The strict journal stores only the original `spec.readNotification` envelope, including notification/run/app/operation identity. It persists before transport, recovers without sending, and clears only after an exact acknowledgement and successful durable CAS. `retry()` sends the same original request. A first-attempt definitive rejection can be acknowledged. A command that previously had an uncertain outcome remains uncertain even if later access is denied; that denial does not prove whether its original write committed. It must be retained until authorized reconciliation is possible. No refresh or route mount automatically replays any write.

Root supplies `NotificationsProvider services={{inbox,runs,resolveRuntime,openTarget}}` above the routes. `runs(appId)` returns an account-owned `AutomationRunsController({appId,transport,lifetime,onUnauthenticated?})`; each page calls `spec.runs`, so the backend checks current builder authorization, including after archival. Root must dispose these controllers with the account epoch. The provider may receive `null` while signed out or reconciling a session.

`resolveRuntime(appId)` must resolve the current authorized **live** adapter. `inbox.openTarget(item,resolveRuntime,openTarget)` confirms the loaded notification still matches, rejects preview/foreign adapters, reads `adapter.get(recordId)`, verifies the exact collection/record and unchanged immutable version, and fences disposal before navigation. Root's `openTarget(VerifiedNotificationTarget)` should synchronously focus/navigate the matching current runtime, or maintain the account fence if it awaits more work. A target marked unavailable by the backend is never followed. The owned `/inbox` and `/apps/[appId]/runs` routes use this injected provider; RootProvider, registry and navigation entry buttons are root integration work.

`withReminders(base,transport,lifetime,{effects})` composes with the media/runtime adapter and preserves every delegated capability, read/write method and base approval list. Optional `setActive` pause/resume and the second image-upload context argument are passed through, so outer wrappers retain lifecycle and media authorization bindings. Pass **confirmed operational** `spec.capabilities.effects`; parser vocabulary and definition requests are insufficient. Empty effects do not advertise reminder support. Recreate/reconfigure the host wrapper if operational capabilities change. `reminderState` uses the authoritative version-bound per-rule states, not `approvedRuleIds`. The existing renderer displays the resulting label without requiring a new enabled-rule DTO. Disabled/unenrolled/unset/failed/suppressed states never become scheduled; a backend pending state is labelled pending, without promising scheduler execution or delivery. No recipient identities are returned, stored or rendered.

Pagination is explicit and fenced by read sequence, account lifetime and current cursor. Refresh wins over older pages; duplicate/repeated cursors fail without duplicating items. Labels describe loaded pages, never global notification/run totals. These tests use simulated transports and local stores; they are not live Appwrite, worker timing, native, provider or browser interaction proof.
