# AppSpec domain foundation

This directory decodes the full AppSpec v1 language for a future React Native renderer. `decodeAppSpec` validates a plain bounded JSON snapshot against the Function package's fixed exported schema, normalizes Dart serialization defaults, then validates semantic references and required capabilities. `tryDecodeAppSpec` provides a safe failure result. There is no schema compilation, generated model code execution, expression evaluation, network, storage, timer, or native operation here.

`schema.json` is a runtime copy of `appwrite_backend/packages/appnest_spec/schema/appspec-v1.schema.json`; the tests read that canonical source and every original fixture directly and fail on schema drift. Update the copy together with the authoritative Dart contract. The schema interpreter supports only the keywords that this fixed schema uses and fails closed on unknown schema keywords. It is not a general-purpose JSON Schema library.

Exports include all eight field types, twenty-one views, seven actions and three policies; navigation, appearance, automation and typed options; collection/field/action/view/page lookup; visible/editable bindings; display-only clock/timer defaults; device capability requests; typed query/value checks; compatibility checks; and deterministic canonical JSON. These types describe the language, not the capabilities currently implemented by the client or backend handlers. The authenticated Dart Function remains the ultimate authority for definitions, hashes, access and commands.

`canonicalAppSpec` mirrors Dart `toJson` omission rules: absent appearance/navigation/view options stay absent; empty optional lists/choices/options are omitted where the Dart model omits them; explicit false page dates are normalized away; collection behaviors, view labels and action arrays use the original serialized defaults; accent colors normalize to uppercase. It preserves the original exported fixture JSON. JavaScript cannot retain an input JSON number's integer-versus-double lexical identity, so this module does not issue authoritative candidate hashes or replace the Function's hashes.

Timestamp values require explicit timezone-bearing ISO calendar instants and reject invalid calendar rollover before UTC normalization. Fractional microseconds are retained. This intentionally enforces the documented valid-date contract rather than relying on permissive JavaScript date parsing; backend validation must enforce the same intended boundary. Civil dates in current flat Tinkerloom definitions remain a separate type and are never silently converted to timestamps.

`decodeDefinitionDocument` explicitly distinguishes `appspec-v1` from `tinkerloom-bounded-v1`. The latter delegates to the existing bounded model with additional strict key/size checks; it does not pretend that the current flat fields, civil dates, long text, or loaded-record agenda have full AppSpec semantics. This bridge does not migrate records or rewrite receipts.

Tests of this domain establish parsing/binding/compatibility behavior only. They do not establish rendered UI, authenticated runtime handlers, effects, AI, media, native builds, device access, or full migration acceptance.
