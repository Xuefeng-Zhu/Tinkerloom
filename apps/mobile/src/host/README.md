# Live host services

`createHostStorage({endpoint, projectId, accountId, appId})` selects the native or web implementation and returns `{lifetime, storage, commands, timers}`. Own one lifetime above live mini-app routes. Dispose it synchronously when the signed-in account, backend, project or app changes. Disposal fences late private reads/writes and releases associated device bridges; it does not delete the original account's retained command. Load a fresh authorized runtime manifest before reading recovery state. `RuntimeController.recover()` only reads; the user must explicitly retry or acknowledge a saved request.

Command input, immutable version/action identity, record revision and operation ID are stored together. A different pending operation or changed input under the same operation ID is rejected. Failed persistence sends no command through this layer, and corruption is surfaced without silently replacing it. A successful server operation's command is cleared only for the matching operation ID. Timer state contains UTC deadlines, not background jobs or scheduled notifications.

The returned `storage` also supplies generic bounded JSON `read(kind)`, `write(kind, value)`, `compareAndSwap(kind, expected, next)` and atomic `change(kind, pureUpdate)` for retained builder/publication/generation envelopes. Writes/CAS snapshot their JSON before awaiting, reject executable hooks, and preserve the exact app/review hash/revision/content supplied by the caller. `null` deletes an entry; `change` callbacks must be pure because browser CAS can reevaluate them. Reserve `command`, `timer:*` and `device-consent` for the strict record/timer/device adapters; use separate names such as `builder-command` for other command kinds. The host must enforce that each generic command has an immutable operation identity and explicit retry policy.

On web, IndexedDB stores AES-GCM ciphertext and nonextractable WebCrypto keys in separate object stores. Additional authenticated data binds each entry to its backend/project/account/app and entry kind. Atomic compare-and-swap transactions prevent competing tabs from overwriting unresolved operations. No localStorage or plaintext fallback is used. Browser eviction, user-cleared data and compromised code running on the same origin remain outside these storage guarantees.

On iOS/Android, payloads are encrypted with Expo Crypto AES-GCM into immutable files under the private document directory. Only a 256-bit key and small commit pointers enter Expo SecureStore; a five-MiB command never becomes one SecureStore item. The pointer is committed after the encrypted file write. A lost pointer response fails the save but retains a possibly committed file for later exact recovery. Superseded encrypted files are removed after commit; failed cleanup can leave an encrypted orphan. Keys/pointers use `WHEN_UNLOCKED_THIS_DEVICE_ONLY` on iOS, and the SecureStore plugin configures Android backup exclusion. Missing keys/files and authenticated decryption failures are errors, not an empty recovery result.

`createDeviceBridge(storage, requestedDeviceCapabilities(spec))` implements the renderer's `DeviceBridge` plus `initialize()`, `setActive(bool)`, `subscribe/getSnapshot`, `setGrant`, `resetGrants` and `openSettings`. Initialize it, activate it only while the live mini-app is visible, and subscribe to its access snapshot when rendering consent controls. `available` includes only requested, supported, explicitly consented capabilities while active and foreground. New scopes start with access off. Previously saved consent can be loaded for that same scope, but no control is automatically replayed on resume. Preview must keep its existing isolated adapter and receive neither host store nor device bridge.

Device information is a fixed coarse allowlist: battery/charging, model/OS, connection type, language, region and time zone. Values stay on the device and are not persisted here. No device name, serial, OS identifier, IP, SSID, precise location or arbitrary native operation is exposed. Reads and permission lookups are fenced after revocation/account closure. Flashlight camera permission is requested only on an explicit flashlight action; returning from the permission sheet requires another explicit action. No preview, photograph, video, audio recording or barcode API is used.

The local `modules/tinkerloom-device` module checks hardware availability and acknowledges native torch calls (Android waits for the torch callback). It scopes torch, brightness and keep-awake ownership by an opaque host lease. Native lifecycle callbacks restore prior brightness/awake state and release owned torch effects even if JavaScript is suspended. The JS bridge also releases on view exit, background, revocation and disposal, and fences late effects. Haptics use Expo Haptics after local consent; OS/hardware conditions can suppress felt feedback. Web exposes these native device capabilities as unavailable, without simulated success.

Verification in this chunk: 18 source/adapter tests cover real AES-GCM with an injected file/pointer port, five-MiB recovery, uncertain pointer commits, scope isolation, concurrent pending writes, generic builder review snapshots/CAS, invalid timer reset, consent defaults, revocation, view exit, late reads/effects and permission-sheet behavior. A standalone browser bundle of the actual browser adapter passed 12 checks in Chrome (large encrypted recovery, four scope boundaries, operation conflicts, competing IndexedDB connections, nonextractable keys and ciphertext), 5 generic builder-command/CAS checks, then 3 more after page reload. The browser harness is `/private/tmp/tinkerloom-host-browser-kiqg2v6z`; it makes no backend calls. Native module autolinking resolves on both platforms; CocoaPods metadata and Swift syntax parse. These are not native build, native restart/storage, OS-permission, physical-device or integrated renderer acceptance results. The final native builds and device validation remain separate gates.
