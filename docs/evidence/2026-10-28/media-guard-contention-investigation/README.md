An additional original M06/V13/V14 defect remains: distinct image reads run with concurrency 2 (`media/controller.ts:296–310`). Each starts `spec.media.status`, which stages app/workspace guards; each subsequent `spec.media.read` stages guards before and after Storage bytes are read (`private_media.dart:483–523`). Those operations bypass the current shared FIFO. Concurrent mounted images can therefore make one another return `transaction_conflict`. `PrivateImage` retains the error until its adapter/asset/image-revision dependencies change (`renderer/fields.tsx:78–104`).

`probe.dart` exercises the actual `PlatformService` and media fixture, with an optimistic in-memory store and fake Storage. It pauses one guard transaction and runs another. Each of status/status, read/read and read/query returns 409+200 when overlapping and 200+200 when sequential. Reported business row counts and file identities remain unchanged; this is not a claim of no guard writes or a Cloud timing reproduction. The first harness attempt used the wrong collection ID and is preserved separately; the corrected probe discovers the template collection ID and asserts every expected result.

Root has approved this narrow correction for the separate runtime_reads stage; it remains pending integration/verification. This audit does not implement that change.
